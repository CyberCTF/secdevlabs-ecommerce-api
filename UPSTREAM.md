The app folder [`owasp-top10-2021-apps/a1/ecommerce-api`](https://github.com/globocom/secDevLabs/tree/10be438496e928c66567749f0aaf0bb976052bc9/owasp-top10-2021-apps/a1/ecommerce-api) of that commit is vendored unchanged, without its Git history,
split so that each part sits in the build folder of the machine that uses it:

| Upstream path (in the app folder) | Here |
| --- | --- |
| `deployments/mongo.Dockerfile` | `build/mongodb/app/deployments/` |
| everything else | `build/api/app/` |

Each `build/<machine>/Dockerfile` says in its header comment how it differs from upstream:

- `build/api/`: upstream's `deployments/api.Dockerfile` with the environment of upstream's compose file baked in (`ENV`), a fixed database user and password where upstream's `make install` generates random ones, a compile at build time so `go run` starts offline, and the compose command as `CMD`. The compose file's unused `/var/lib/docker` volume is left out.
- `build/mongodb/`: upstream's `deployments/mongo.Dockerfile` (`mongo:4.0.3`). Its `mongo-init.js` is generated by upstream's `app/scripts/generate-passwords.sh` and not committed, so `build/mongodb/mongo-init.js` is that script's output with the fixed values.

To update, replace the vendored folders with a newer secDevLabs commit, then change this file.
